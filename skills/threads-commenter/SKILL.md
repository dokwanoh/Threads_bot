# Threads Commenter

Read [the shared protocol](references/shared-protocol.md) first. Use the latest approved task/automation scope, current deployed documents, dot cloud browser, existing history/login, and exclusive shared writer. Do not treat this skill as permission to answer any new feed post.

## Find unanswered existing conversations

1. Inspect new activity on our existing posts and conversations containing our prior participation. Verify that qualifying relationship from actual posts/replies, not a notification label alone.
2. Open the exact new incoming comment and enough surrounding conversation to understand it. Identify the actual parent permalink, author, chronology, original media where relevant, and all our existing responses.
3. Exclude comments already answered, duplicate incoming content, old resolved conversations, advertising, reciprocal-follow bait, spam, harassment bait, and sensitive content that needs user judgment. Do not resume a previous unknown or denied action.
4. Check both shared ledger history and fresh UI for any response already attached to this exact parent. A wording change or another role never makes a duplicate target eligible. If we already replied, skip even when a proposed answer differs.

## Reply usefully

Draft a short, natural Korean 반말 reply that directly answers the new point and contributes something useful. Verify technical claims against the original material or primary sources. Avoid generic praise, copied replies, invented personal experience, and unnecessary questions. If a meaningful answer is unavailable, skip rather than manufacture engagement.

Freeze the exact target and reply payload; run the full claim → read-only absence check → begin-write → one browser submission → submitted → persisted readback → verify cycle from the shared protocol. Reload and verify the exact authored reply belongs to `aitr.endradar`, has the intended text and actual parent, and has its own owned permalink. Ambiguous outcomes stop all further writes, with no duplicate submission.

Do not like, repost, or follow in the commenter role. If a participant appears worth following, hand the parent/spreader the verified profile URL and concise public rationale for later review; the handoff is not follow permission and is not a completed action. Do not move into random new-post replies to fill idle time.

Release and ask the parent to finish the verified checkpoint acknowledgement, even when an acquired run found no eligible replies. Report actual KST start/end times, newly verified replies and direct links, already-answered/skipped counts, candidate handoffs separately, and any blocker. An empty eligible queue is a valid result; do not invent a minimum reply quota.
